How it works

From a folder of code to a live address

You talk to your assistant. It talks to bitploy.

1

Install it on one server

A fresh Ubuntu server and a domain. The install script sets up Docker, Traefik, the firewall and HTTPS.

$ sudo bash install.sh
2

Connect your AI

Create a token in the dashboard and add bitploy's MCP server to Claude Code, Cursor or any assistant that speaks MCP.

https://yourdomain.com/mcp
3

Ask for a deploy

The assistant checks the Dockerfile, sends the code and waits for the build. You get the address.

Features

Everything an app needs to stay online

Your assistant uses all of it through MCP. You find the same things in the dashboard.

Dockerfiles ready for

Anything else that has a Dockerfile, a published image or a compose file runs too.

Built for AI agents

More than 50 MCP tools, and a REST API that does the same. Every error has a code and a hint the assistant can act on, so it fixes a failed deploy without you reading a log.

// get_deployment
"state": "failed",
"error": {
  "code": "unhealthy",
  "message": "The app did not answer.",
  "hint": "It listens on localhost; make
    it listen on 0.0.0.0:$PORT"
}
assistant fixes the port and deploys again

Push to deploy

Link a GitHub repository. Every push to the branch builds and goes live.

Databases in one step

Add a database next to your app on a private network. bitploy generates the passwords and sets DATABASE_URL.

Backups and rollbacks

App data is backed up every night and kept for 14 days. A bad release rolls back to the version before it.

14 nightly backups

Locked down by default

Each app runs in its own container on its own network, and cannot reach the server or other people's apps.

What you need

  • One Linux server. 4 vCPU, 8 GB RAM and 160 GB disk is a good start for a small team.
  • A domain. Apps go on its subdomains, like shop.yourdomain.com.
  • An AI assistant with MCP. Or use the dashboard and the REST API yourself.

Then connect your assistant

Create a token in the dashboard and add bitploy as an MCP server. This is the command for Claude Code.

The Connect AI page in the dashboard has the setup for Claude Desktop, Cursor and VS Code too, with your address and token filled in.

your computer 
$ claude mcp add --scope user --transport http bitploy \
    https://yourdomain.com/mcp \
    --header "Authorization: Bearer YOUR_TOKEN"

FAQ

Questions people ask first

What does it cost?

Nothing. bitploy is open source under the MIT license. You pay for the server you run it on.

How is it different from Coolify, Vercel or Fly.io?

bitploy starts from the AI assistant instead of the dashboard: the assistant gets its own tools for every step, deploy rules it reads before it begins, and errors that say how to fix them. The dashboard is for watching and stepping in. Like Coolify, it runs on a server you own.

Which AI assistants work with it?

Claude Code, Claude Desktop, Cursor, VS Code and other tools that can connect to an MCP server over HTTP. The dashboard shows the setup for each one.

Can I use it without an AI assistant?

Yes. The dashboard deploys from a GitHub repository, a zip or the catalog, and the REST API offers what the MCP tools offer.

What can it run?

Anything with a Dockerfile, any published Docker image, static sites, and compose files with up to 6 services. Small apps keep their data in SQLite under /data; bigger ones get a database next to them.

Does it run on more than one server?

No. bitploy is built for one server: one binary, one SQLite file, no cluster to manage.

Where does my data live?

On your server. Each app's files are in its own volume, with nightly backups you can download or restore from the dashboard.
