# Build contract for parallel agents

Five agents build bitploy at the same time in one working tree. Read SPEC.md
(the product spec) and this file before writing code.

## Ownership

Each agent owns its files. **Never edit a file you don't own.** Stubs with the
right signatures already exist for every service method; implement the
bodies, keep the signatures. If you need something from another area that
isn't there, add a private helper in your own file rather than editing theirs.

| Agent | Owns |
| --- | --- |
| **auth-api** | `internal/auth/**`, `internal/app/accounts*.go`, `internal/api/**`, `cmd/bitploy/**`, queries `accounts.sql`, `api.sql`, migrations `00010`–`00019` |
| **deploy** | `internal/deploy/**` except `dockerfile*.go` and `git*.go`; `internal/dockerx/**` except `stats.go`, `events.go`; `internal/proxy/**`; `internal/app/apps*.go` plus new files `internal/app/deploy_*.go`; queries `apps.sql`, `deployments.sql`; migrations `00020`–`00029` |
| **mcp** | `internal/mcp/**`, `internal/templates/**`, `internal/deploy/dockerfile*.go`, `internal/deploy/git*.go`, `internal/app/catalog*.go`; queries `catalog.sql`; migrations `00030`–`00039` |
| **web** | `web/**` except `web/embed.go` |
| **ops** | `internal/domains/**`, `internal/metrics/**`, `internal/app/ops*.go`, `internal/dockerx/stats.go`, `internal/dockerx/events.go`, `deploy/**`, root `Dockerfile`, `.dockerignore`, `README.md`, `.github/**`; queries `ops.sql`; migrations `00040`–`00049` |

Shared files (`service.go`, `types.go`, `config.go`, `apperr.go`) may get
**small additive edits** (a new field, a new helper) when there is no other
way. Re-read the file right before editing, keep the edit minimal, never
rename or remove anything, and mention it in your final summary.

## Rules

- **Database**: add queries only to your own `.sql` file. Query names must be
  unique across all files — check with `grep -h '^-- name:' internal/store/queries/*.sql`.
  Regenerate with `~/go/bin/sqlc generate` (it rewrites `internal/store/db/`
  from all files; that's fine). Schema changes go in a new migration in your
  number range (`000NN_what.sql`, goose format), never by editing `00001`.
- **Go deps**: everything in the spec is already in `go.mod`. Don't run
  `go mod tidy` (the integrator does). If you truly need a new module, `go get` it.
- **Building**: build and test your own packages
  (`go build ./internal/deploy/... && go test ./internal/deploy/...`). Other
  agents are editing at the same time, so a compile error in a file you don't
  own is probably work in progress: wait a minute and retry; don't fix it.
- **Errors**: every failure returned to a user is an `*apperr.Error` with a
  plain-words message and an exact hint. Codes are snake_case and shared
  between REST and MCP. Run user-visible text through `apperr.Redact`.
- **Audit**: every service method that changes state calls `s.Audit(...)`.
- **Docker**: `s.Docker` may be nil (tests, `admin` commands). Check before use.
- **Tests**: table tests as the spec asks. Integration tests against real
  Docker go behind `//go:build integration`.
- **Decisions**: when the spec is ambiguous pick the simpler option and append
  one line to `docs/decisions.md` (append only; others write to it too).
- Don't add features that are not in SPEC.md. Don't `git commit` (the integrator does).
- Never run destructive commands on anything outside this repo; Docker
  containers/networks/images you create in tests must carry the
  `nl.bitploy.managed=1` label or a `bp-test-` name and be cleaned up.

## Cross-area conventions

- **REST JSON**: lists return `{"items": [...], "next_cursor": "..."}` (`app.Page[T]`).
  Errors: HTTP status from `apperr.Error.HTTPStatus` and body
  `{"error": {"code", "message", "hint", "next", "details"}}`.
- **Dashboard auth**: `POST /api/v1/auth/login {email, password}` sets the
  session cookie; `GET /api/v1/session` → `{user, csrf_token}`; every non-GET
  request sends `X-CSRF-Token`. In dev (`BITPLOY_DEV=1`) the cookie is
  `bitploy_session` without `Secure`; in production `__Host-bitploy_session`.
- **Health checks through Traefik**: bitploy (in a container, or on the host in
  dev on macOS) cannot reach app containers directly. During `health_check`,
  the deploy code writes the app's route file with `Route.Candidate` set; bitploy
  then probes `cfg.TraefikInternal + health_path` with
  `Host: proxy.CandidateHost(slug)`. Traefik has an unpublished entrypoint
  `internal` on `:8081` for this (dev publishes it on `localhost:8081`).
  Traefik is connected to every `bp-<slug>` network (container `cfg.TraefikContainer`).
- **Catch-all**: Traefik sends unknown `*.<app domain>` hosts and each extra
  app domain itself to bitploy (`cfg.InternalURL`). The root router renders
  "No app here" / "This app is stopped" for any Host that is a subdomain of an
  app domain (`AppsDomain` or an extra one), or an extra domain itself (looked
  up as its root app), and isn't the public URL's host. `_catchall.yml` is written at
  startup and again whenever an admin adds or removes an app domain
  (`Service.ApplyAppDomains`).
- **App domains** (`internal/app/app_domains.go`, `internal/domains/appdomain.go`,
  migration `00200`, queries `app_domains.sql`): extra wildcard domains in
  `app_domains` (certificate PEM, private key sealed with `store.Crypto`, AAD
  `app-domain-key\x00<id>`), grants in `user_app_domains`, and
  `apps.base_domain` (`''` = the default domain). An app's address is
  `cfg.AppURLOn(slug, app.BaseDomain)` everywhere (`App.url`, `App.domain`,
  deployment `url`, the deploy log's `Live:` line, `BITPLOY_URL`); the route Host
  is `cfg.AppHostOn`. Slugs stay globally unique. `Me.app_domains` lists the
  domains a user may use (default first; admins: all). `CreateAppInput.domain`,
  `UpdateAppInput.domain`, `CatalogDeployInput.domain` and the MCP `domain`
  argument go through `pickAppDomain` (403 `domain_not_allowed`). Admin API:
  `GET/POST /admin/app-domains`, `PUT /admin/app-domains/{id}/certificate`,
  `DELETE /admin/app-domains/{id}` (409 `app_domain_in_use` while apps use it),
  `PUT /admin/users/{id}/app-domains {domain_ids}`. The key is never returned.
  Certificates are written as `<RoutesDir>/certs/<domain>.crt|.key` (0600) and
  `_certs.yml` (`tls.certificates`, paths under `/dynamic`).
- **An app on the domain itself** (migration `00390`, `apps.on_root` plus the
  partial unique index `apps_root_domain` on `base_domain WHERE on_root = 1`):
  an admin with a dashboard session sends `UpdateAppInput.slug = "@"` (with or
  without `domain`) to give an app the root of an extra app domain
  (`https://<domain>`). The slug does not change. Refusals: 403
  `root_admin_only` (not an admin, or an API/MCP token), 422
  `root_default_domain` (the default domain, or no domain), 422
  `root_reserved` (the apex is the public URL's host or `BITPLOY_EDGE_HOST`),
  409 `root_custom_domain` (the apex is a custom domain of an app), 409
  `root_taken` (another app holds it; the message names it), 400
  `root_no_address` (a worker), 400 `slug_invalid` (`@` on create). Any other
  slug, or a `domain` move without `@`, frees the root at once (no 30-day
  reservation); a rename frees it too. A root app's address is
  `cfg.AppRootURL(domain)` everywhere `AppURLOn` is used (`App.url`, deployment
  `url`, `Live:`, `BITPLOY_URL`, notifications, MCP); `App.root` is `true` and
  `App.domain` stays the domain. `<slug>.<domain>` keeps routing. The route
  file `app-<slug>.yml` gets a second router `app-<slug>_root` with
  `Host(<domain>)`: `tls: {}` when the domain's stored certificate covers the
  apex (its SANs), else `tls.certResolver: letsencrypt`. `Me.app_domains[]`
  gets `root_allowed`, `root_app` (slug) and `root_dns` (one DNS line) for
  admins on extra domains whose root may be claimed; `GET /admin/app-domains`
  items get `root_app {slug, name}` or `null`.
- **Local dev**: `BITPLOY_DEV=1 BITPLOY_APPS_DOMAIN=localhost BITPLOY_APPS_SCHEME=http
  BITPLOY_APPS_PORT=8000 BITPLOY_PUBLIC_URL=http://localhost:5173
  BITPLOY_TRAEFIK_INTERNAL_URL=http://localhost:8081
  BITPLOY_INTERNAL_URL=http://host.docker.internal:8080 BITPLOY_DATA_DIR=./.data`.
  Traefik runs in Docker with the web entrypoint on host port 8000.
- **Traffic stats** (`internal/traffic`, `internal/app/traffic.go`, migrations `00090` and `00180`, queries `traffic.sql`):
  Traefik writes a JSON access log to `<data dir>/traefik/logs/access.log`; bitploy tails it,
  maps `RouterName` (`app-<slug>@file`, custom domains `app-<slug>_<host with _ for .>@file`, names from
  `proxy.RouterName` / `proxy.HostRouterName`; only domains in `issuing_cert`/`active` have a router) to an app, and keeps only counts. Never store an
  IP address, user agent or query string. `GET /api/v1/apps/{app}/traffic?window=24h|7d|30d|today` returns
  `{app, window, granularity, visitors_today, totals, previous, points, pages, countries, referrers, not_found}`;
  `totals` and `previous` are `{requests, visitors, errors (5xx), error_rate, client_errors (4xx), bots, page_views, timed, slow, median_ms, p95_ms}`, `previous` is the
  equal period before (its last hour or day counted for the share of the current one that has passed) and `null` for `today` or when the stats (or the app) do not go back that far; points carry
  `client_errors`, `bots`, `page_views`, `median_ms` and `p95_ms` too. Answer times (migration `00280`, `traffic.SpeedBounds`) are counts per bucket
  (under 50, 100, 200, 500 ms, 1, 2, 5 s, slower) per hour and day, for people's non-file requests that reached the app (Traefik's `Duration`, not when
  `OriginStatus` is 0, not for 101); `median_ms`/`p95_ms` are estimated from the buckets (5000 means 5 s or more) and `null` without timed answers; `slow` is answers of 1 s or more. Lists hold the top 10; the referrer `(direct)` is page views without a `Referer`.
  `&list=pages|countries|referrers|not_found` returns only that list, up to 500 rows (other fields empty); any other
  value is 400 `invalid_list`. Retention: day totals 61 days, everything else 30.
  The fields kept in `deploy/traefik/traefik*.yml` and the ones read in `traffic.ParseLine` go together.
- **/data backups** (`internal/app/backups*.go`, `internal/api/endpoints_backups.go`, migration `00080`, queries `backups.sql`): `GET /apps/{app}/backups` returns `{items, settings, restore, busy, total_bytes, upload_max_bytes}` (newest first; `restore` is `{backup_id, state, error, started_at, finished_at, app_restarts}`); `DELETE /apps/{app}/backup-restore` forgets a finished restore (409 `backup_busy` while it runs); MCP: `create_backup`, `delete_backup` and `set_backup_schedule` (deploy scope), `list_backups` and `get_storage` (read), no restore tool by design; download needs the deploy scope or a session (`token_read_only` otherwise); `POST /apps/{app}/backups` starts a manual backup and answers 202 with a `running` backup; `POST /apps/{app}/backups/{id}/restore` answers 202 and progress is in `restore` of the list; `DELETE /apps/{app}/backups/{id}`; `PUT /apps/{app}/backup-settings {schedule: off|daily|weekly, keep_mode: last|days, keep}`; `settings` is `{schedule, keep_mode, keep, time_utc, next_at}` where `time_utc` (HH:MM) is the app's backup time, from a hash of its id, between 02:00 and 06:00 UTC. Default on (migration `00300`, `apps.backup_schedule_set`, `apps.backup_default_at`): an app whose schedule was never set gets daily, `days`, 14 when it has `/data` on and is not Valkey, Redis or Meilisearch (on create, `add_service`, `PATCH volume=true`, after a deploy, and in the backup loop); the first one waits for the next backup time. Saving the settings marks the schedule set; bitploy never changes a set schedule. Two plain handlers outside huma, behind the same auth (bearer or cookie, CSRF on the upload) but without the 8 MB body cap: `GET /apps/{app}/backups/{id}/download` (attachment, Range supported) and `POST /apps/{app}/backups/upload` (raw `.tar.gz` body). Errors: `backup_busy`, `volume_not_ready`, `backup_not_found`, `backup_not_ready`, `backup_file_missing`, `backup_invalid`, `backup_too_large`, `volume_off`, `storage_quota_exceeded`, `server_disk_full`, `backups_not_needed` (409: a Valkey, Redis or Meilisearch app has no backups; refused for back up now, upload and a schedule other than off, and the scheduler skips it). App and usage JSON carry `backups_mb`; App JSON carries `backups_supported` (false for those three).
- **/data file browser** (`internal/app/volume_files.go`, `internal/dockerx/volfiles.go`, `internal/api/endpoints_files.go`; helper containers only, never exec in the app): `GET /apps/{app}/files?path=` returns `{path, items: [{name, type: file|dir|symlink|other, size, modified_at}], truncated, upload_max_bytes}` (read scope; folders first, at most 1000 items); `POST /apps/{app}/files/folder {path, name}` answers 201; `DELETE /apps/{app}/files?path=` answers 204 (a folder goes with its content, a link is removed and not followed, /data itself is refused). Two plain handlers outside huma: `GET /apps/{app}/files/download?path=` (attachment, regular files only) and `POST /apps/{app}/files/upload?path=<folder>&name=<file>[&overwrite=true]` (raw body, up to 100 MB and the free room of the /data limit; answers 201 with the entry; an existing file needs `overwrite=true`, else 409 `file_exists`). Changes and the download need the deploy scope or a session (`token_read_only` otherwise); only the owner, never an admin. Paths are relative to /data; `..`, control characters and symbolic links in a path are refused (`path_invalid`, `file_symlink`). Changes take the backup lock and the app lock (`files_busy`, `app_busy`); a running restore refuses everything (`backup_busy`). The app is not paused, so a database file copied while the app runs can miss recent writes. Errors: `volume_off`, `volume_not_ready`, `path_invalid`, `name_invalid`, `name_missing`, `file_not_found`, `not_a_folder`, `not_a_file`, `file_exists`, `file_symlink`, `file_too_large`, `volume_full`, `files_busy`, `files_unavailable`.
- **GitHub App** (`internal/github/**`, `internal/app/github*.go`, `internal/api/endpoints_github.go`, migration `00100`, queries `github.sql`; the old per-user token is gone, migration `00100` drops `users.github_token_enc`, `github_login` and `github_token_expires_at`): one GitHub App per instance (table `github_app`, one row; private key, client secret and webhook secret sealed with AAD `github_app:<field>`), created by an admin through GitHub's manifest flow. Users link installations with `github_installations` (primary key user + installation id; `status` is `active`, `suspended` or `deleted`) after an OAuth code exchange and a check against `GET /user/installations`; an `installation_id` from a query string is never trusted alone. `github_installations.github_login` is the GitHub user who proved access and `limited` is 0 only when that user owns the (personal) account; for limited links `github_user_repos` (user + installation + lowercase `owner/name`) holds the repositories GitHub says the user can open, and only those are picked, cloned or deployed on push. `github_installation_repos` holds the repositories of `selected` installations (lowercase `owner/name`). An app created without a webhook (public URL unreachable) stores an empty `webhook_secret_enc`; its `push_status` is `no_webhook` and the admin view has `push_events: false`. `GitHubInstallation` gains `limited`. `github_deliveries` holds webhook delivery ids for 7 days (dedupe). `apps` gains `git_auto_deploy` (default 1) and `git_last_push_at`.
  - Routes: `GET /github` (app info and the caller's installations), `POST /github/connect {mode: install|authorize}` (returns the GitHub URL, state is sealed and expires in 15 min), `POST /github/link {code, state, installation_id?}`, `DELETE /github/installations/{id}`, `GET /github/repositories?q=`, `GET /github/branches?repo=`; admin: `GET /admin/github`, `POST /admin/github/manifest {name, organization?}`, `POST /admin/github/manifest/complete {code, state}`, `DELETE /admin/github`; apps: `PUT /apps/{app}/git-source` (also takes `auto_deploy`), `PATCH /apps/{app}/git-source {auto_deploy}`, `DELETE /apps/{app}/git-source`. The `/github` and `/admin/github` routes are session-only; the app routes take a token with the deploy scope.
  - Webhook: `POST /api/v1/github/webhook`, outside session auth and CSRF. The signature (`X-Hub-Signature-256`, HMAC-SHA256, constant-time compare) is checked before the body is parsed; body cap 5 MB; `X-GitHub-Delivery` dedupes; the answer is `202` and only queues. A failed handler forgets the delivery id so GitHub's redelivery works.
  - Deploys from a push use channel `github` and record `commit_sha` and `commit_message`. A push deploys an app only when: it is a branch push (not a tag, not a deletion), the repository (case-insensitive, `.git` ignored) and branch match, `git_auto_deploy` is on, the app is not stopped, the app owner linked `installation.id`, and the installation's account is the repository owner. Older queued deployments of the app are cancelled, so quick pushes build only the newest commit.
  - Clone credentials for `github.com` come only from the app owner's own installations (a narrow, read-only token for that repo, cached until 5 minutes before expiry); otherwise the clone is anonymous. Other hosts are always anonymous.
  - Config: `BITPLOY_GITHUB_URL` and `BITPLOY_GITHUB_API_URL` (defaults github.com and api.github.com). CSP `form-action` allows that web origin, for the manifest form post.
  - Error codes: `git_source_linked` (409, upload refused on a git-linked app), `github_access_missing` (422, replaces `github_token_missing` and `github_repo_forbidden`), `github_app_missing`, `github_app_exists`, `github_app_rejected`, `github_app_broken`, `github_state_invalid`, `github_code_invalid`, `github_code_missing`, `github_installation_forbidden`, `github_too_many_accounts`, `github_not_installed`, `github_repo_not_connected`, `github_unreachable`, `github_signature_invalid`, `github_delivery_missing`, `github_payload_invalid`, `github_payload_too_large`.
  - `App.git_source` is `{repo_url, branch, subdir, repo?, repo_html_url?, auto_deploy, push_ready, push_status, push_message, last_push_at?}`. `push_status` (computed from the database, no GitHub call) is `ready`, `off`, `other_host`, `app_missing`, `no_webhook`, `not_connected`, `no_access` or `reconnect`.
- **Password protection** (`internal/app/protection.go`, `internal/proxy/auth.go`, migration `00110`, query `SetAppProtection`): `PUT /apps/{app}/password-protection {enabled, username?, password?}` (session with CSRF, or a token with the deploy scope) returns the `App`; MCP `set_password_protection` calls the same `SetPasswordProtection`. `App` JSON carries `protected` (bool) and `protected_username` (only while on); the password and its hash are never returned, logged or audited. Errors (4xx, each with a hint): `username_required`, `username_invalid`, `password_required`, `password_too_short`, `password_too_long`, `password_invalid`, `protection_needs_web_app`; `route_not_updated` (500) if the route file could not be written (the setting is saved and the reconciler retries). The Traefik middleware is `app-<slug>_auth`, on the subdomain and custom domain routers only. Traffic ignores access log lines that Traefik answered itself with 401 (`OriginStatus` 0), so `deploy/traefik/traefik*.yml` must keep `OriginStatus: keep`.
- **Public ports** (`internal/app/public_ports.go`, `internal/portproxy`, `internal/dockerx/portproxy.go`, `cmd/bitploy` `port-proxy`, migration `00270`, queries `public_ports.sql`, `deploy/firewall.sh`): `App.public_port` is always present: `{available, reason?, enabled, running, service?, host?, port?, address?, target_port?, connection_url?, allow_from: [], expires_at, opened_at?, error?}`; `reason` is `public_ports_off` or `web_app`; `connection_url` (service template apps) has every generated password as `********`. `PUT /apps/{app}/public-port {enabled, service?, close_after?: 1h|24h|never, allow_from?: [cidr], only_my_ip?}` (session with CSRF or a deploy token; owner only) returns the `App`; `close_after` defaults to `1h` when opening and is counted from the call; `allow_from` left out keeps the list, `[]` clears it. `POST /apps/{app}/public-port/reveal` returns `{connection_url, address, secrets: {VAR: value}}` (owner, deploy scope; audited `app.public_port_revealed`). Admin (session only): `GET /admin/public-ports` returns `{enabled, from, to, host, per_user, open: [{app, app_name, owner_email, service?, port, allow_from, expires_at, opened_at, error?}]}`; `DELETE /admin/public-ports/{app}` answers 204. MCP `set_public_port(app, enabled, service?, close_after?, allow_from?, only_my_ip?, show_password?)`. Errors (each with a hint): `public_ports_off` (422), `public_port_web_app` (422), `public_port_no_port` (422), `public_port_limit` (409), `public_ports_full` (503), `public_port_busy` (409), `public_port_changed` (409, another call or the reconciler opened, changed or closed the port at the same moment; nothing changed), `public_port_failed` (503, the port is saved and the reconciler retries), `public_port_close_failed` (503), `public_port_closed` (409, reveal without an open port), `no_connection_url` (422), `close_after_invalid`, `allow_from_invalid`, `my_ip_unknown` (400), `my_ip_not_ipv4` (422), `service_required`, `service_not_for_single_app` (400), `service_not_found` (404). Config: `BITPLOY_PUBLIC_PORTS`, `BITPLOY_PUBLIC_PORTS_PER_USER`, `BITPLOY_PUBLIC_PORTS_HOST`. Forwarder containers are `bitploy-port-<app id>` with label `nl.bitploy.public_port=<app id>` and no `nl.bitploy.app_id`. Suspending a user closes all their public ports (audit reason `user_suspended`); reactivating opens none.
- **Static sites and turning /data off** (`internal/app/apps.go`, `internal/app/volume_off.go`, `internal/app/deploy_pipeline.go` `settleResources`, migration `00140`, `deployments.build_kind`): `App.static` is true while the live deployment was built from bitploy's `static`, `node-spa` or `node-static` template (`deploy.IsStaticKind`). A static site has fixed 64 MB and 500 `cpu_millis`, is left out of the memory and CPU sums (quota checks, whoami and `GET /usage`; `OpsSumMemoryLimitsMB` still counts it) and keeps counting for the app limit and storage. `PATCH /apps/{app}` on a static site: other `memory_mb` or `cpu_millis` values return 422 `static_fixed_size`, `volume=true` returns 422 `static_no_storage`. - **MCP guidance (2026-11-06 audit)**: `validate_dockerfile` without a Dockerfile answers `ok: true, static: true` (`ValidateResult.static`, REST too) for code a deploy serves as a static site, instead of `dockerfile_missing` and a template. `query_db`/`write_db` on an app whose variables refer to a PostgreSQL, MySQL or MariaDB service of its project answer `db_in_service` (MCP only, next `query_db` or `write_db`) instead of a SQLite path hint. `set_env` `build` values are an enum (`public`, `secret`, `none`) in the schema.
